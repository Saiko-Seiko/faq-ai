# デモ制作ロードマップ（受注率を上げるための最小構成）

## このデモの目的

受注を決めるのはスペック説明ではなく、**クライアントが自分のスマホで触って「動いてる」と体感すること**。
したがってゴールは「完成したシステム」ではなく、**商談で3分で見せ切れる、絶対に落ちないデモURL**。

### 設計の三原則

1. **絶対に落ちない** — 商談中にAPIエラーが出たら終わり。APIキー無しでも完全動作する「デモモード」を標準にする。
2. **URLを送るだけで見られる** — インストール・ログイン・環境構築を相手に一切要求しない。
3. **提案書で言ったことが画面にある** — 特に「最終判断は人」「回答ログを見返せる」。ここが他の応募者との差になる。

### 技術方針と、その理由

| 決定 | 理由 |
|---|---|
| ビルド不要の静的サイト（HTML/CSS/素のJS） | 作業端末に Node も Python も無い。加えて GitHub Pages にそのまま置ける＝クライアントに即URLを渡せる |
| GitHub Pages で公開 | 無料・常時稼働。要件の「24時間いつでも」をデモ自体が体現する |
| デモモード / ライブモードの二段構え | デモモード＝定義済みナレッジから応答（キー不要・無料・確実）。ライブモード＝Claude API を直接呼び、本物のAIだと証明する |
| データは localStorage | デモの範囲。本番はDBに置く旨を README に明記し、誤解を防ぐ |
| 日本語UI・モバイルファースト | 利用者は日本語話者の求職者。スマホ閲覧が主戦場 |

> ⚠️ ライブモードでAPIキーをブラウザに置くのは**デモ専用の割り切り**。本番はサーバ側でキーを持つ。この線引きは README とデモ画面の両方に明記する（クライアントにセキュリティ意識を示せる材料にもなる）。

## 作る順番と、切り捨て基準

商談日が迫った場合の優先順位は **Phase 1 → Phase 3 → Phase 2 → Phase 4**。

理由: Phase 1 は掴み、Phase 3 は差別化。Phase 2 は「面接がAIで回る」ことさえ見えれば、質問数は5問でも3問でも印象は変わらない。**削るなら Phase 2 の深掘り質問と音声入力から。**

## 意図的にやらないこと（デモ段階では）

- ログイン・認証（本番は必須。デモは擬似トークンで代替）
- 本物のDB（localStorage で代替。README に明記）
- 動画の自前配信（サンプル動画を埋め込むのみ）
- メール送信（専用URLの送付は手動想定）
- 実在の会社データ（**架空の会社**で作る。クライアント名は使わない）

## クライアントに確認したい5点（デモ提示と同時に投げる）

1. 説明会の動画は御社でご用意いただけますか（尺・本数・更新頻度）
2. チャットに覚えさせる情報の元資料（会社案内・募集要項・就業規則など）はいただけますか
3. ホームページは WordPress ですか？ 専用ページは埋め込みと独立ページのどちらが良いですか
4. 面接の質問項目と評価基準は、人事のご担当者と一緒に決めさせてください
5. 応募者の回答データはどこに・何ヶ月保存しますか（個人情報の取り扱い方針）
